# 独立代码审查修复验证报告

本报告记录对 `docs/独立代码审查报告.md` 中 1 个 HIGH 与 3 个 MEDIUM 发现的实现和验证；不把冒烟输出表述为正式实验结论。

## HIGH：预处理配置静默忽略
**修复：** `validate_preprocessing_columns` 核验全部原始特征的唯一列策略；`run_one` 先做原始记录分层拆分，再调用仅训练集拟合的 `prepare_numeric`。标识符/删除列被排除；数值中位数、类别 one-hot 集合及标准化只用训练集；验证/测试仅 transform。训练全缺失列和训练常量输出安全删除，未知类别全零编码。结果 JSON 的 `preprocessing` 保存完整策略和拟合审计。

**测试证据：** `test_split_and_train_only_preprocessing` 实际调用拆分和预处理，断言拆分互斥、7:2:1 类别比例、训练中位数、训练均值、ID 排除、类别编码及验证未知类别。`test_run_one_audits_test_isolation_and_pool_count` 实际运行 KEEL 小数据的关键路径。

## MEDIUM：阈值未用于验证与测试
**修复：** 配置加载拒绝 `[0,1]` 外阈值；`evaluate_pool`、基线和最终重训测试均使用同一 `optimization.threshold`，并记录 `decision_threshold`。

**测试证据：** `test_nondefault_threshold_changes_validation_objective` 使用确定性概率 `[0.4, 0.6]`，证明 0.5 与 0.7 产生不同混淆矩阵和 FNR 目标；端到端测试同时断言优化报告与最终测试记录为 0.7。

## MEDIUM：default 正式配置不可运行
**修复：** 原 `default.json` 已更名为 `formal.template.json`，其中 `requires_user_label_semantics_confirmation=true`，且 CLI `run` 会拒绝该模板。模板保持正式 N=K=20、100 代边界；`smoke.json` 保持明确的 N=K=4、2 代边界。

**测试证据：** `test_configuration_threshold_profiles_and_formal_template` 加载两份配置，断言其参数边界和模板确认标识，并验证非法阈值被拒绝。

## MEDIUM：关键数据隔离与运行约束测试缺失
**修复：** 优化接口只接受训练/验证参数；运行审计明确测试集不进入 `evaluate_pool` 或 PROMETHEE。候选选择不可用槽位会失效。运行保存初始池与每代 trial 池逐槽 manifest，并记录 `pool_count=1+generations`。

**测试证据：** `test_selected_unavailable_slot_is_invalid` 验证不可用槽位；`test_run_one_audits_test_isolation_and_pool_count` 断言 3 个池（G=2）、逐池 manifest 和测试隔离；既有测试继续覆盖跨池 uid 拒绝及最终重训逐槽 f/i。
