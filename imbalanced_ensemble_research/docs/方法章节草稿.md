# 第三章 方法（非虚构草稿）

## 3.1 研究流程、列策略与数据隔离
针对二分类不平衡任务，先在原始记录层面按 7:2:1 进行分层训练、验证与独立测试划分，且三组索引互斥。每个原始特征必须在配置中且只能在四类之一出现：直接删除列、标识符列、数值列或类别列。删除列与标识符列在任何拟合前去除。数值缺失值由训练折非缺失中位数填补；类别缺失值使用训练内 `__MISSING__` 类别，并用仅由训练折类别建立的 one-hot 编码表示。验证/测试中未出现于训练折的类别编码为全零。训练全缺失列及训练常量编码输出安全删除；中位数、类别集合、未知类别计数、删除理由和标准化均值/标准差全部写入审计产物。标准化仅由训练折拟合，验证集仅用于候选评价，测试集不参与特征、实例、模型或参数选择。标签含义、潜在时间/组依赖及标签派生字段需结合数据来源进一步核查。

## 3.2 统一编码与基学习器池
候选表示为 `x=(f,i,m,w)`：f、i、m 分别为特征、训练实例和池内模型选择段，w 为连续加权段。前三段以阈值 0.5 二值化；空选时保留最大分量对应的最低索引。实例段还按训练标签补足每类一个确定性样本，以保证二分类 RBF-SVM 可训练。每个槽位训练一个由该槽位 f/i 决定的 RBF-SVM，并写入 GenerationPoolManifest。该清单含 pool_uid、代号、槽号、染色体号、f/i、派生种子、特征/训练索引哈希、SVM 参数和修复记录。不可训练槽位标记为 unavailable；选择该槽位的候选无效而非静默降级。

## 3.3 spMODE-II-inspired 优化原型
本研究实现为 spMODE-II-inspired 工程原型：初始化评估一个 N=K 的父池；每个进化代仅生成一个 N=K 的 trial 池。未改变父解复用已验证目标及其最后绑定清单。候选只可用同 pool_uid 内的 m/w 融合槽位概率。验证优化最小化由 `optimization.threshold` 概率决策得到的 FPR、FNR 与复杂度 C，其中 C 的特征、实例、模型、权重集中项系数依配置为 0.35、0.35、0.20、0.10。运行保存全部 `1+G` 个池清单及阈值。原始 spMODE-II 的支配、档案和变异细节未在本项目中核验，故不得称严格复现。

## 3.4 PROMETHEE 决策与独立测试
从末代存活且有效的非支配候选中，以所有目标最小化的 V-shape 偏好计算 PROMETHEE 净流；默认无差异与严格偏好阈值 q=0.01、p=0.05，权重为 0.45、0.45、0.10。选定候选与其绑定清单逐槽重训，再以同一 `optimization.threshold` 在未参与优化的测试集评估一次。此处不得以验证指标替代测试结论，也不得写入未实际运行的性能或显著性结果。
